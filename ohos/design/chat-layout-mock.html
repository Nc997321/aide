会话页排版草案

V1 时间线内瞬态行（已选定）：工具运行时消息流里出现一行「正在执行 ××」，本轮结束整行淡出消失。历史里永远只有思考卡 + 对话。代价：行的出现/消失会让时间线轻微跳动。
权限应答 · 计划批准（ExitPlanMode）：plan 模式的出口确认——呈现的是「批准这份计划」而非「允许一次工具调用」。计划正文（input.plan）按消息区同一 Markdown 管线渲染，一屏限高内滚：批准前必须能读完全文，且「批准并执行 / 继续修改计划」恒在卡尾、不被长计划推出屏外。「批准并执行」带 nextMode='auto'（sidecar 切模式后开始执行）；「继续修改计划」走两步式拒绝（理由可留空），模型改完再送一版计划。
权限应答 · 澄清提问（AskUserQuestion）：模型在等你的「回答」而不是「允许」。逐题整行选项卡（圆点 + 选项 + 描述），「其他」行内直接输入回答；未作答前「提交回答」置灰。多题时逐题纵向排列、多选题带「可多选」标签，全部作答后提交门才开。跳过 = 无理由拒绝，模型自己想别的办法。作答打包 answers 走 permission_response。
权限应答 · 工具调用（含 Bash）：一个动作一行——允许（主按钮）/ 拒绝（次按钮）整行排布。拒绝走两步式：点拒绝原地展开理由输入（可留空）→ 确认拒绝 / 返回；理由走协议 message 通道，模型能看到为什么被拒。
弹窗期间输入框隐藏：挂着未决请求时，新消息本就会排队等这轮答完，与其留着占屏不如整块让位；答完输入框回归。并行请求 FIFO：永远只确认队头，卡片头部显示「还有 N 条排队」。
通用语义：工具事件只进瞬态 liveActivity，不进消息流，回合结束清空（= 不驻留内存）；历史加载时跳过 tool_call 块；卡片一律白底描边、间距走 8 的倍数、图标统一 SVG。
后台任务（bg_task_*，停靠区同款）：状态条胶囊有任务才出现（● N 个运行中 + 命令名），点开看任务列表（状态/命令/走表时长/终止）+ 尾部输出贴尾滚动（移动端不做 xterm）。跨轮次存活——回合结束不清，bg_task_ended 才收；全部完成后状态条变 ✓ 停留数秒淡出。桌面端 BgTaskDock 同语义。
