原型结构 · v3 底稿的增量层

  • 底稿不动：连接屏 / 抽屉 / 供应商 / 三档思考全部沿用 ../remote/index.html（app.html 由底稿字节级复制后只加日常增量）。
  • 进屏即日常：新桌面初始 = 「日常」范围的空态新会话（不预载工程历史）；demo=1 显式要求时才切 aide 播底稿流式剧本。
  • 弹层首行「日常」：对话气泡头像（对齐桌面侧栏日常分区）+ 暖橙「默认」角标 + 定位副标题，无路径行。
  • 工作区卡：日常态显示「日常」+ 副标题占掉路径行；路径是内部概念，任何 UI 不出现。
  • 空态与输入：归属行「发消息即创建 · 日常对话」（不点名工作区）；placeholder 换「今天帮你做些什么？」。
  • 切范围 = 回范围默认档：日常→快速，工程→均衡；跨屏同步同规。日常剧本走快速问答链路（无工具行，usage 尾注 effort low）。

产品规则 · 判定 / 默认 / 降级

  • 手机默认就是日常：连接后浏览范围与发消息落点默认「日常」，不是「跟随桌面」。
  • 显式选择让位：用户切到某项目后，本次 App 运行内以选择为准；重启回落默认日常。
  • 判定单一：isDailyKey(key)，键与桌面注册同链（normalize → path_to_key），无第二套规则。
  • 日常永不激活：daily_workspace 纯查询身份，不改变桌面活动工作区；手机侧纯浏览。
  • 旧桌面降级：无该 RPC → 日常行不存在、默认回落第一个项目、零报错面；每次运行只探测一次，失败静默。
  • 记忆优先：会话内手动升档仍被记住（协议 session_effort），范围默认只在新建会话时生效。

数据与协议 · 桌面侧已就绪

  • REGISTRY 已收录 daily_workspace（rpc.rs:89 + 回归测试 registry_exposes_daily_workspace），handler 纯转发 commands::workspace::daily_workspace()，cargo test --lib 921 全绿。
  • 返回 { key, path }：key → list_sessions_for_workspace({wsKey}) 拉日常会话；path → 首条消息 send({..., workspaceRoot: path}) 定落点。
  • list_workspaces 服务端已剔除日常，手机端列表无需再滤。
  • 纯计算无 IO、无参数、无副作用；不进 connection_fingerprint（不影响重连判定）。
  • 单会话归属可用 session_workspace 比对，但按需过筛：本原型不新增该 RPC，用打开会话时的浏览范围即可判定。

实施清单（ohos 工程 · 本页只出原型，未动代码）

  • sdk/types.ets：加 DailyWorkspace { key, path } DTO。
  • sdk/api.ets：加 dailyWorkspace(): Promise<DailyWorkspace>，照 listWorkspaces() 形态；头注收录清单同步。
  • WorkspaceModel.ets：daily 缓存 + isDaily(key) + 每运行探测一次（失败静默）+ 默认选中日常（userPicked 让位）+ selectedRoot()/selectedDisplayName() 日常特例（最关键：root 必须回 dailyPath，否则 spawn 落回桌面活动工作区）+ loadMetas 纳入 daily 键。
  • ChatDrawer.ets：弹层首行（气泡 SVG + 默认角标 + 副标题、无路径）；工作区卡日常态。
  • ChatPage.ets：空态归属行日常变体 + placeholder「今天帮你做些什么？」。
  • ChatModel.ets：syncModelEffort 插日常判定（新会话看 selectedKey，已开会话复用 store.spawnWsKey=打开时范围），默认档 low；打开会话时 spawnWsKey = sessionsModel.wsKey。
  • 会话列表：默认范围拉 list_sessions_for_workspace(dailyKey)。
