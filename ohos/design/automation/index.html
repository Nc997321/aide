▾结构说明 · 每屏要点 · 协议缺口 · 实施清单

原型结构 · iframe 拆分（与 design/remote 同构）

  • app.html = 应用本体：五屏共用一份 DOM 与状态，URL 参数决定初始形态（?screen=drawer / detail / editor[&mode=new] / run / playbook）。与未来 ArkTS 结构一一对应：ChatDrawer 内嵌自动化区段（位置已定稿：紧跟工作区卡；曾备选「会话列表之后」，已撤）+ TaskDetail / TaskEditor / RunTranscript / PlaybookSheet 四个浮层组件，全部不注册路由（main_pages 仍只有 pages/Index）
  • index.html = 展台：手机框 + iframe + 演示胶囊，postMessage 遥控 + 状态中继，纯布景
  • 聊天主屏 / 抽屉其余部分沿用 design/remote，本页聊天仅作布景

每屏要点

  • 抽屉区段（位置定稿：紧跟工作区卡）：标题呼吸点 = 有任务在跑；行 = 名称 + 调度摘要 + 上次结果 + 启用开关；可折叠；空态 / 拉取失败态内置
  • 详情：chips 概览 + 立即运行 / 编辑 / 删除 + 指令卡（折叠展开）+ 手册卡三态 + 统计条 + 运行记录九要素行（状态 / 触发 / 模式 / 时间 / 时长 / 轮次 / 成本 / 摘要 / 跳过原因），skipped 行置灰不可点
  • 编辑器：基本 / 执行配置 / 权限与安全 / 调度 / 通知五区段；模型选项取自当前供应商的本地模型列表（与聊天模型 chip 同源，不调用远程 getDefaultModel）；调度 kind 与协议判别联合 1:1（每天 / 每周 / 每月 / 间隔 / 单次）；connectors 只读
  • 运行转录：只读时间线（手册注入标记 / 思考卡可折 / 工具行 / usage 尾注），加载更早；不做实时流
  • 手册：只读 + 过期横幅；生成 / 更新回桌面

协议缺口（桌面端 · 本页只标注不改码）

  • ① REGISTRY 未开放 11 个 automation 命令——真机拉取必败，屏 1「拉取失败」态即此场景；需在 remote/rpc.rs 注册 + handlers 薄包装
  • ② automation_run_finished / automation_missed 未进 chat_events_tx——live 状态改由 run 原始事件流推导：session_init 的 run_ 前缀建别名 + 终态事件（message_stop / error / session_dead）触发列表刷新对账
  • ③ 自动化转录在 scoped 目录（~/.aide/scopes/automation/…），load_messages 读不到——运行转录先出空态，桌面补齐后点亮

实施清单（ohos 工程 · 本页只出原型，未动代码）

  • sdk：22 个类型 + 11 个命令封装过筛进 ohos（automation.ts 为唯一上游事实源）
  • AutomationModel：@ObservedV2 单例，list / detail / stats / runs 四组缓存 + 第三路 chat-event 监听（run 流推导）
  • 组件：ChatDrawer 内嵌 AutomationSection + TaskDetail / TaskEditor / RunTranscript / PlaybookSheet 四浮层
  • 接线：ChatPage 弹层管理 + Index 返回键；storage 增「自动化任务页」缓存；effort 三档文案 快速 / 均衡 / 极致

未采纳（v1 明确不做）

  • 连接器增删：协议可配但 UI 复杂，v1 只读展示，编辑保留原值
  • 实时流式转录：打开历史 run 只读，运行中刷新按钮回查
  • 本地通知：通知由桌面系统发出，鸿蒙端只看结果
  • 手册重新生成（redistill）：回桌面操作
  • 运行上限（最大轮次 / 成本上限）：v1 表单不暴露，编辑时保留桌面端原值
  • 生效窗口 valid_from / valid_to：桌面设置，表单不暴露
