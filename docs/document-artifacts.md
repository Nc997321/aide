# 文档成果展示协议 v1

桌面聊天里的文档成果卡片只提供文件入口，点击复用现有文件弹窗，不增加阅读面板。

## 声明格式

agent 成功写入用户要求交付的文档后，在最终回复中输出顶层围栏：

````markdown
```aide-document
{"version":1,"path":"docs/design.md","title":"设计方案","summary":"交互规则与实现步骤"}
```
````

- `version`：固定为数字 `1`。
- `path`：当前会话 Host 上的真实文件路径，相对路径以会话工作区为根。支持 `.md`、`.markdown`、`.txt`；不接受 URI、行号、查询参数或控制字符。
- `title`：非空纯文本，最多 200 字符。
- `summary`：可选纯文本，最多 500 字符。

只用于明确交付的文档，不用于普通回答、只读参考文件、源代码、配置或失败的写入。此声明是 agent 的成果描述，不作为文件已经存在的后端证明，因此卡片不显示“已写入”等验证状态。

## 传输与恢复

声明随现有 assistant text 事件广播、随 transcript 原文保存，不添加命令、事件或本地乐观状态。桌面在消息定稿后调用 `@aide/sdk/utils/documentArtifacts`，删除有效声明的展示正文并集中展示卡片。同一消息内按解析后的路径去重，后出现的标题和摘要生效；不同消息保留各自交付记录。

顶层完整围栏才会被解释。未知版本、无效字段、未闭合围栏和不支持的格式保留原文；引用、列表、外层代码示例以及用户消息不转卡片。旧消息没有声明时保持原样。

鸿蒙端已按同一协议接入聊天卡片，点击复用原有 Host 文件预览浮层。其 ArkTS 纯函数实现与 SDK 用共同用例对账；只在 assistant 消息定稿后解析，用户消息和文件预览中的协议示例不转卡片。remote-pwa 尚未适配，未识别的客户端仍可阅读 JSON 中的路径和标题。

## 打开行为

窗口所属 Host 决定文件来源，使用该消息的会话工作区解析路径，直接打开对应文件弹窗，不按同名文件搜索。缺失和读取失败沿用弹窗的错误展示。卡片不嵌入文档副本；重复打开会刷新干净窗口，保留未保存编辑（包括刷新等待期间开始的编辑）。

宿主提示在 query 创建时注入，已经运行中的 query 要重建后才会获得新提示。历史纯路径不会自动猜测为成果卡片。
