# 计划批准后交给子会话执行

计划待批准保留「手动确认编辑」「使用 Auto 模式」，增加「交给子会话执行」。只在受信任工作区、非自动化、非子会话且 aide-sessions 已挂载的主线程计划中提供。子代理的计划不提供此入口。

按钮发送 `permission_response.planExecution = "subsession"`，不放行主会话的 `ExitPlanMode`。sidecar 保持主会话的计划模式，反馈用户批准的是移交执行，请模型利用已有上下文整理探索摘要。摘要通过原有 `session_spawn` 的 `exploration` 参数交接：发现与位置、已知文件、已执行检查、未决问题。真实批准的计划由宿主原样附入任务，不依赖模型重述。不会 fork 主会话或复制完整历史。

子会话复用 Host 既有启动、工作区、供应商、模型、档位、权限与回报通道；权限模式为 Auto，审批按钮的说明会显示这一点。交接阶段不能自行换模型。同一委派只启动一个新子会话，并发或重复调用不会重复派发；缺摘要时尚未启动，可以补全已有信息；Host 失败或启动状态不明时不自动重试。

减少重复探索使用交接说明引导，不引入读取文件、搜索或测试的工具白名单。模型自主判断实现需要的代码读取、验证，以及事实缺失、过时或冲突时的定点核查。主会话收到成功结果后简要通知并结束本轮；子会话继续实现并回报。保留原有子会话深度、并发与权限规则。

`plan_delegation`（`preparing` / `spawned` + `childId` / `failed` / `cleared`）经 Host 的 chat-event 总线广播。审批只由 `permission_cancelled` 广播撤下，命令写入失败时保留入口。父会话顶部关联到子会话原有的任务清单，不复制任务状态；可打开现有子会话面板。交接关联是运行期状态，重启后仍可从侧栏打开子会话，顶部关联暂不落盘。

交接摘要的完整性和是否遵循探索建议取决于模型。自动化测试验证审批、交接载荷、重复派发、失败与进度广播，不代表已经验证真实模型的遵循度或节省比例；可用本地 usage 日志分析实际成本。
