## 1. 背景与问题

### 1.1 AI 做出来的东西没有归宿

Aide 里 AI 的产物今天只有一个落点：**工作区文件夹**。

写代码时这是对的——代码的归宿就是仓库。但 AI 现在做出来的东西很多不是代码：一份调研报告、一个能打开的网页、一张表。它们混在项目文件里，跨项目拿不出来、没法预览、没法当"作品"复用。下次想要，只能去翻转录。

### 1.2 与 WorkBuddy「资料库」的对照（已实地盘过）

对照对象是 `workbuddy.cn` 的一个公开团队空间。它的模型是三层：多格式产物存储（含 html/csv）+ 与 Agent 共同编辑 + 团队协作（评论/权限/实时协同）。教程之外，从其网络请求可验证到的底座：节点树 `space → nodes`（kind 有 doc / folder / **web**）、每节点 version + publishVersion、可发布成 `workbuddy.link/p/<id>`、roles + collaborators + public_permission、按 `node:<id>` 通道的实时协同订阅、discussions/comments、20GB 配额。其高阶玩法「工作台」是**自带数据库的 HTML 页面**（页面 ↔ CSV 双向绑定）。

**结论：偷它的内核，不走它的路。**

- **内核（要偷）**：产物有归宿——存得进去、下次拿得出来、能发给别人看。
- **它的路（不走）**：库是这个产品的中心、一切在云上、团队协作是主场景。Aide 的中心是会话 + 工作区 + git；照搬会造出**第二份真相**（同一份内容既在工作区又在库里各自腐烂）。

### 1.3 现状：库只认一种东西

`knowledge-server` 把「文档」等同于「一段 markdown 文本」：`revisions.content` 是正文，图片只能作为 md 的附件（`assets` 挂在 `document_id` 上）。后果是**库里躺着一张图，agent 读不到**——在"库是给 agent 用的"这个定位下这是硬伤。

所以"支持的文件类型太少"不是缺几个格式，是**内容模型只有一维**。

## 2. 定位

**做**：Aide 的**产物库**——AI 做出来的东西放这里，我下次拿得出来，agent 也读得到。使用者是「我 + 我的 agent」。对外只开一扇窗：**发布/分享**（只读）。

**不做**：团队协作台。评论、多人共同维护、实时协同不在本设计内。

理由（三条，与 §1.2 的对照直接相关）：

1. **agent 跑在用户自己的机器上**是 Aide 的架构支点。团队空间里没有常驻 agent，"同事和 Agent 在同一份内容上持续协同"只能落成"同事能改文档，但叫不动 agent"——砍掉的正好是最值钱的一半。
2. **工作区是真相**。单人时"库里的副本 vs 工作区的原件"已经是烦恼；多人共同维护同一份内容时，它从烦恼升级成一致性事故。
3. **产品中心会漂移**。Aide 是个人工作台，不是 Confluence。

> 真要做团队空间，那是 `knowledge-server` 那条线的产品（它本来就是邀请制、多用户、可私有化部署的服务），应当作为独立产品立项，而不是给 Aide 加功能。本次不展开。

## 3. 产品路线图

### 第一步：能放进去、能打开看

库能装 AI 做的**网页**（今天只装文档）；**而且你自己能传**——不再只能靠跟 agent 说一句。传进去以后在 Aide 里点开就能看：网页在右栏浏览器里跑起来。顺带**不用再单独登录**：资料库变成 Aide 的一部分。

> 做完之后：AI 给你做了个报告页，存进库；下次点开就看。你自己手上的文件也能直接传进去。

### 紧接着的独立一轮（不属于上面三步）：看清谁改的

翻历史时一眼看出哪条是**AI 改的**、来自哪次会话，点了能跳回去——设计见 §4.4。

**它不依赖第一步的任何东西**，排在哪都行；定的是**紧跟第一步**。理由：AI 写入**今天就在产生**（agent 早就能通过 MCP 往库里写），所以"分不清谁写的"是**当下就在疼**的问题，不是等"收编"做完才出现的。

### 第二步：存和取都变成一句话

- **存**：AI 在工作区里做出了 `report.html`，说一句「存进资料库」就进去了；库里记着**这是哪次会话、哪个项目做出来的**。
- **取**：库里的东西能拿回会话接着改，不用复制内容、重新解释背景。

> 做完之后：这次会话做出来的东西，下次会话直接接着用。库到这一步才算"活"。

### 第三步：发出去

库里任何一样东西能生成**一条链接**，别人用浏览器打开就能看——不用装 Aide、不用注册账号。网页天生适合这么发，所以从它开始。

### 记着但先不做

图片、PDF、Excel 进库（第二刀，见 §8）；团队协作（另一条产品线）。

## 4. 核心决定

### 4.1 内容模型：条目 = 原件 + 可读表示

从「markdown 文档」泛化为**条目**：一个 mime + 一份内容 + 一份可搜文本。

内容形态分两类，**本设计只落第一类**：

| 形态 | 原件是什么 | 存法 | 本次 |
|---|---|---|---|
| **文本形态** | 本身就是文本（md / html / txt 及其同类） | `revisions.content` | ✅ 本次只落 html，见 §5.1 |
| **字节形态** | 字节：图片 / pdf / xlsx / zip | blob（复用 `assets` 的 BlobStore） | ❌ 第二刀 |

三个判断：

**(a) 不为"以后可能要用"加列。** 这个仓库已经有四处死 schema（`tags`+`document_tags`+`links` 三张零引用表、`status` 永远停在 draft、`document_acl` 建了没接口、pgvector 备好没启用）。字节形态的列**第二刀再加**——加可空列本来就廉价，先加速反而制造第五处死 schema。

**(b) 拆开两个消费者，它们要的不是同一个东西。**

- **可搜文本（给检索）**：剥掉标记的纯文本（html 剥标签）。要的是词，可以失真。
- **agent 读（给使用）**：**优先给原件**。文本条目直接给原文——agent 可能要**改**它，剥过标签的 html 是废的。字节条目才给抽取文本，并明示"这是抽取的、可能失真"。

**(c) 预览方式不进数据库。** 存 mime，渲染器按 mime 在前端分派。加预览器不用迁移数据、不用碰服务端。

### 4.2 收编 = 快照，不是链接

「存进库」就是拍下那一刻的快照。之后工作区怎么改都不影响库。库里只记来源（哪个工作区 / 哪条路径 / 哪次会话哪一轮）用于溯源，**不做同步**。

理由：如果库里存的是"指向工作区文件的指针"，工作区一移动就断链、跨设备就废、发布就没有内容可发。而如果做双向同步，就是 §1.2 说的第二份真相。快照是唯一诚实的语义。

### 4.3 身份：免登录 ≠ 无认证（硬约束）

「不用再单独登录」免掉的是**门槛**（要你输账号密码），不是**身份**。身份由 Aide 本地持有凭据、自动登录。

链路：**一次性登录 → 服务端签发会话凭据（64 位十六进制随机串）→ Aide 存在本地 → 每个写请求带 `Authorization: Bearer` → 服务端按 sha256 查 `sessions` 表拿到 `user_id`**（`api/extract.rs:53-69`）。库里**只存凭据的 sha256**（`api/extract.rs:22-29`），明文只在用户机器上；因此伪造的代价 = 偷到那份凭据，安全等级 = 该机器的安全等级。

两条硬约束，不可为省事破坏：

1. **作者身份必须由服务端从凭据推断，绝不能由发送方自己声明。** 否则谁都能声称自己是别人——这条与「免不免登录」无关，就算保留登录，允许客户端自填作者也是漏洞。
2. **不得实现为"本机的请求一律信任"。** 那等于拆锁：机器上任何程序（含恶意软件、共用电脑上的另一个人）都能以用户身份写入。免登录只能是"凭据由 Aide 替你带着"，不能是"不用凭据"。

**凭据的有效期今天会打脸"免登录"**：`KB_SESSION_TTL_HOURS` 默认 14 天且**没有续期**（`config.rs:43`；`api/extract.rs:61` 只判 `expires_at > now()`）。也就是说"不用再登录"实际是"14 天内不用登录"，第 15 天打开面板照样落登录页。

**决定：做成滑动续期 + 绝对上限。** 一直在用就一直不用重登；凭据最长活 N 天（建议 90），到期必须重新登录一次。代价要说清：滑动续期会让**泄露的凭据"只要攻击者一直在用就不过期"**——绝对上限就是给这一点兜底的。这是第一步范围内的服务端改动（落在 §5.5 那条线上）。

### 4.4 作者维度：人 / AI + 会话 + 模型

单人场景下"作者=我"这个信息没有用（反正都是自己）。真正要区分的是：

- 这条内容**是我写的，还是 AI 写的**？
- 如果是 AI——**哪次会话、哪个模型**？能不能翻回去看当时怎么做的？
- 人机一起改的改动——**哪段是 AI 改的、改之前什么样**？

否则库里躺着一堆内容，分不清哪句是自己想的、哪句是 AI 顺手加的，"我来把关"就是空的。

**问题的形状**：单人场景下"作者=我"这个信息没有用——**库里所有条目、所有版本，作者字段都是同一个人**（agent 用的是同一份凭据，见 §4.3）。真实的历史列表长这样：

```
v3  09-30 14:02  heaven  补一节用法
v2  09-30 11:40  heaven  改标题      ← 其实是 AI 改的
v1  09-29 20:11  heaven  初稿        ← 其实是 AI 写的
```

所以"作者"这一栏今天**等于没有**。

**机器看的 vs 人看的**：凭据（sha256）是机器看的标识；**显示名是给人看的标识**——这一层已经在了（`types.rs:142` 的 `display_name`、`types.rs:174` 的 `author_name`，前端历史列表已经在显示）。本节要做的是**让它重新有信息量**。

#### 人看到的标签怎么写

| 谁写的 | 标签 |
|---|---|
| 人 | `heaven` |
| AI | `AI · 《会话标题》 · 模型名`，例：`AI · 一季度复盘 · deepseek-v4-pro` |
| AI 但拿不到会话标题 | `AI · 会话`——**不编**，宁缺毋滥 |

#### 三处显示 + 一个筛选

1. **历史列表**每行（`KbHistory.vue` 已有位置）
2. **条目头部**：显示最后改动是谁——「最后由 AI 改于 09-30 14:02」。今天只有翻进历史才看得到
3. **人机用同一个图形标记**：AI 用 `--aide-agent-accent`（粉）的 `✦`——这是仓库既有的 agent 语义色，**不新造一套**
4. **历史列表加筛选**：全部 / 我改的 / AI 改的

#### "为什么"比"谁"更重要

真正会问的不是"这行谁写的"，是"这段为什么长这样"——而答案在**会话里**。所以：

- **AI 那一条要能点，点了跳回那次会话**。桌面端能跳；远端客户端跳不了 → 显示为**不可点**，不假装
- 列表里同时给一句**改动摘要**：MCP 写工具加一个"这次改了什么"的参数，**建议填**（工具描述里说明为什么值得填）。不强制——模型不填就是空的，不编

#### 记录什么（第二步的数据变更）

`revisions` 加四列：`author_kind`（`human` / `ai`，默认 `human`）、`session_id`、`session_title`（**写入时的快照**——会话标题会变、会话会被删，不能指望事后查得到）、`model`（后三者仅 AI 写时有值）。

**可信度分两级，两级都要关死**：

- **"谁"（账号）**：服务端从凭据推，**不可伪造**（§4.3 硬约束 1）。
- **"来源"（哪次会话 / 是不是 AI）**：**同样由服务端从凭据推，不由发起方声明**。→ **已定（2026-09-30）：做绑定会话的独立凭据。**

#### 已定：绑定会话的 agent 凭据

> 如果只让工具参数里带 `sessionId`，那它就**只是声称**——只能在自己名下撒谎、冒充不了别人，但确实能把 AI 写的说成自己写的。这个口子不堵，等于白记。

形状：

1. 每条会话启动时，Aide 主进程用**用户凭据**换一张**会话令牌**（请求里带该会话 id）。
2. 服务端签发时把 `(user_id, session_id)` 绑进去，token 只存 sha256——**与用户凭据同一套存法**。
3. sidecar 用这张令牌调库；服务端鉴权时认出它 → `author_kind = 'ai'`、`session_id` **从凭据里取**，工具参数里传什么都不作数。
4. 会话结束 / 进程退出 → 令牌失效。

**换不到令牌不能让会话起不来**：资料库连不上、没登录、服务没起——这些都**不许阻塞会话启动**。降级形态是"这次会话里知识库工具报『资料库暂不可用』"，而会话照常跑。会话是主功能，资料库是附加能力，不能反过来。

**权限边界（不许越界）**：令牌**派生自用户凭据、绑同一个 `user_id`**，权限判定完全不变（还是那个用户的空间与角色）。它只多带一个"来自哪次会话"的标注，**不是新身份、不放大任何权限**。

**两个方向都关死**：agent 令牌写的一律标 `ai`；人写的一律标 `human`。人拿不到 agent 令牌，agent 也变不成人。

**通道必须按会话隔离**：**不能用现在那份全局的 `~/.aide/knowledge*.json` 镜像**——那样一个 sidecar 进程里的所有会话会共用同一个来源标注。会话令牌的传递通道（会话级 env / 会话级配置文件）在第二步的设计里定。

**`session_title` 仍然只能是写入时快照**：会话标题会变、会话会被删，事后查不到，所以每次写入时把标题一起记下来。

**不做**：令牌不带细粒度授权（"只能写某空间"之类）。权限 = 用户权限，有意如此。

#### 明确不做

**行级归属**（"这行字具体是谁写的"）——那是 CRDT / 操作流那一类东西，本设计不碰。我们做到"每个版本 / 每次改动"这一级就停。

变更卡（会话侧）上的同一套标记属于会话那条线，不在本设计内——但**标记形态要统一**（同一个 `✦` + 同一个语义色），不许两套。

### 4.5 发布窗口：只读 + 不透明链接（硬约束）

发布是**主动开给外网的唯一一扇窗**，必须：

- **只能看、不能写**，且**只能看那一份**——不是打开整个库；
- 链接是**不透明的一次性凭证**，与账号凭据完全分离；链接泄露 = 泄露那一份的阅读权，不泄露账号；
- **写操作永远要账号凭据**，拿链接的人碰不到。

### 4.6 预览与发布共用一条渲染通路

右栏浏览器要打开库里的 HTML，就得有一个它能访问的地址。而库的接口要 Bearer，浏览器的 `<img src>` / 导航发不出 Authorization（这正是 `assetLoader.ts` 走 fetch → objectURL 的原因）。

所以不另造预览通道，而是：**每份可渲染产物有一个"取件地址"（不透明 token）**。

- **预览** = 这个地址在本机可达，**临时**（用完即失效）；
- **发布** = 同一个地址通过 nginx 暴露到外网，**显式动作**产生、**稳定**（撤销发布才失效）。

第三步之所以便宜，就是因为预览这一刀已经把通路建好了。

> ⚠️ **前置 spike**：右栏浏览器能否用这个地址加载库里的 HTML（含脚本、相对资源），以及 blob: 方案是否可行，开工前先验证（见 §6 验收 0）。

## 5. 第一步的实现设计

### 5.1 能装什么：只加 **html**

**先纠正一个范围错误**：本设计早期版本把 csv / json 也列了进来，那是照抄 WorkBuddy 的花色，**不是我们产品的东西**。事实：

- Aide 全仓**没有任何 csv 处理**（grep 零命中），json 也没有专门处理。
- Aide 自己的文件类型词汇只有两种：`useFileViewer.ts` 的 `isMarkdown`（可渲染预览）、`FileWindow.vue:78` 的 `canOpenInBrowser = isHtmlFilePath(...)`（可在浏览器打开）。**markdown 与 html，就这两个。**
- 我们也没有"表格预览"这种界面——凭空造一个不在本产品语汇里的东西，就是把别人的产品抄进来。

所以第一步**只加 html（连同 htm）**。csv / json 这类文件连 ingest 也不放行（§5.6：不认的格式当场拒绝），而不是"收下但显示成一堆看不懂的文本"。

| 类型 | 为什么 | 可搜文本怎么来 |
|---|---|---|
| **html** | agent 生成最多；产品本来就会把它丢进浏览器打开；天生可发布 | 剥标签取正文 |

落地方式沿用现有的 `ParserRegistry` 回退链与按扩展名分派（`adapter/parser/`）：**新增一个 parser 后端即可，公共层不动**。这与 `CLAUDE.md` 的"可替换技术藏在端口后面"一致。

### 5.2 数据变更（两列）

| 加在哪 | 列 | 含义 |
|---|---|---|
| `documents` | `mime text NOT NULL DEFAULT 'text/markdown'` | 决定预览分派、图标、给 agent 的类型提示 |
| `revisions` | `search_text text`（可空） | 派生可搜文本；`md` 条目等于 `content` |

`tsv` 生成列与搜索高亮片段的取值改为 `coalesce(search_text, content)`——md 条目行为不变，html 条目不再是标签噪音。

**代价（认了）**：md 条目的 `search_text` 与 `content` 冗余一份。理由是 `002_search.sql` 已经写明的原则——`title_tokenized` / `content_tokenized` 两列留着是为了**可诊断**；派生文本同理。这个模型里 revisions 本来就是全量快照，一份纯文本的冗余可忽略。

`kind`（doc/folder）、`slug`、`title`、树、权限、锁**全不动**。

### 5.3 打开看：预览按 mime 分派

**只有两档 + 一个兜底**，与产品既有的词汇对齐（§5.1）：

| mime | 预览 |
|---|---|
| `text/markdown` | 现有渲染（不变） |
| `text/html` | 右栏浏览器，取件地址（§4.6） |
| 其它 | 转义后的原文——**绝不留白**（防御性分支：按 §5.1 的收录范围，库里到不了这里） |

### 5.4 agent 侧

- `read_document` 对文本条目**返回原件**（html 给源码，不给剥过的文本）——agent 要能改它；
- 新增条目类型对 agent 天然可见（`list_documents` / `search` 不变）；
- **不改工具集**：本次不加新工具。

### 5.5 收进本体：不用再单独登录

凭据存在哪**不变**（现有 localStorage + 镜像到 `~/.aide/knowledge*.json` 供 agent 侧读取的机制保持），变的是**用户不再需要看到登录界面**：面板启动时自动用已有凭据登录；只有"凭据缺失/失效"这一种情况才需要用户介入。

配套的服务端改动是 §4.3 定下的**滑动续期 + 绝对上限**——否则"免登录"每 14 天就破功一次。§4.3 的两条硬约束在此同时生效。

### 5.6 上传入口：人主动放东西进去

原文只写了"库能收"，没写"人能放"——那等于只有 agent 写得了（`ingest_file`），人想存个东西只能跟会话说一句。**那不叫"能放进去"。** 所以补一个上传入口。

- **前端**：树上方一个「↑ 上传」，选文件后走 `POST /api/ingest`（multipart，`spaceId` 必填、`parentId` 可选）。这条后端通路**已经存在**，新增的只是前端接线（`kbClient` 加一个 `ingest`）。
- **认哪些格式由服务端说了算**：`GET /api/ingest/formats` 是唯一权威，客户端不预判（沿用既有约定）。第一步之后是 `md / markdown / txt / docx / pdf / html / htm`。
- **不认的格式当场拒绝，并说清收哪些**——不许默默收下、再显示成看不懂的东西。
- **大小上限是既有的 32 MiB**（`DefaultBodyLimit`）。超了要给可读的提示，不是裸 413。
- 二进制（docx / pdf）由服务端解析成 markdown 入库，这条既有，不动。

## 7. 已知代价与主动砍掉的东西

**代价**

- md 条目的 `search_text` 与 `content` 冗余一份（§5.2）。
- **中文命中片段的 `[[HL]]` 只在词被标点/空格隔开时才出现**（2026-09-30 实测）。
  PG 的 `simple` 解析器把一整串 CJK 当**一个 token**，而索引侧是 jieba 分好的词——
  命中靠 `tsv`（分词的那一侧），片段靠原文（不分词的那一侧），两边切法天生不一致。
  影响：命中照旧正确，只是片段可能没有高亮；前端按「没有哨兵」优雅降级成普通文本。
  修它要上 zhparser（我们刻意不引数据库扩展），**认了这个代价，不改**。
- 取件地址只发**一份文本**：自包含的单文件 html 正常，带相对引用（`./x.css`）的多文件产物取不到资源。
- 派生表示**必然失真**：html 剥标签丢结构。所以 agent 读的是原件、可搜文本才允许失真（§4.1b）——这个妥协要一直守住，不能为了省事让 agent 读派生文本。
- 本次只覆盖文本形态；图片/PDF/Excel 仍未进库（第二刀）。

**主动砍掉**

- 评论、多人共同维护、实时协同（§2，另一条产品线）
- WorkBuddy 的「工作台」（HTML ↔ CSV 双向绑定）——Aide 里 agent 能直接改工作区文件，不需要库支持"活的对象"
- **csv / json**——**不是我们产品的格式**（§5.1：Aide 全仓没有 csv 处理，文件类型词汇只有 markdown 与 html）。早期版本把它们列进来是照抄 WorkBuddy 的花色
- xlsx / pptx 解析、富文本编辑、PDF 预览
- 字节形态的一切（含图片独立成条目）

## 8. 后续钩子

> 命名提醒：**「第二步」是产品步骤**（§3），**「第二刀」是内容形态**（字节）。两者不是一回事。

**紧接着的独立一轮：作者维度（§4.4）。** 人 / AI + 会话 + 模型；标签、标记、筛选、点回会话。最贵的一块是"**来源也要不可伪造**"——**已定：做绑定会话的独立凭据**（形状与边界见 §4.4 末）。**不依赖第一步**，只因为排期定在它后面。

## 9. 界面结构（2026-09-30 重做）

第一版做出来的是"一个更整洁的管理后台"：常驻左侧栏 + 顶栏 + 内容区，那是管理系统的形状。**用户判定不合格**（原话："类似管理系统那样，没什么新意"）。重做后定下的结构：

### 9.1 两个全屏态，不是永远的两栏

| 态 | 什么时候 | 长什么样 |
|---|---|---|
| **索引态** | 屏幕没被任何一样东西占着 | 整屏目录。条目是排版主角：行高 44、标题 16px、右侧一列时间对齐成竖线；内容 880 居中 |
| **阅读态** | 有东西开着（文档 / 检索结果 / 成员） | 整屏给它。左上角「资料库」= 返回；正文仍是 720 居中竖轴 |

判据只有一处：`KnowledgeBase.vue` 的 `reading`。

**为什么**：一个人用的库，常驻 280px 导航是过度投资；而阅读才是主要活动。所以导航是一个**态**，不是永久的 chrome。

### 9.2 空间不单独成段

`spaces` 是**权限边界**（服务端 `space_members` 的角色挂在它上面），不是文件夹。**个人库里它是多余的**，所以：**只有一个空间时界面上根本不出现**；有多个时才在目录顶部出现切换。组织靠文件夹。

（把它伪装成树里的父子节点是不诚实的——那是两套语义。）

### 9.3 使用指南是库里的一份文档，不是页面

原来它在侧栏单独占一段、由 `KbGuide.vue` 用写死的字符串渲染：**搜不到、删不掉、不能改名、不随版本更新**，还要和 `KbDocumentView` 各维护一份排版。这是产品里最后一块"第二份真相"。

现在：正文在 `guideText.ts`，索引页脚给一个**一次性入口**「把使用指南存进资料库」；装进来之后它就是普通文档——能改、能删、能被搜到、能被 agent 读。装过之后入口永久消失。

**已知代价**：新实例不会自动带指南（要用户点一下）。做成"初始化写进库"要动服务端 bootstrap，本次没做。

### 9.4 其余约束（视觉）

- 配色 100% 走 `--aide-*`（仓库红线）。**顺手修掉了三个根本不存在的 token**：`--aide-bg-primary` / `--aide-bg-secondary` / `--aide-error`——它们让 markdown 编辑区、修改说明框、保存/取消按钮**全部透底**，登录卡没有卡面色，红色永远走硬编码兜底。另有两处硬编码 `#fff` 压在 accent 上（暖色主题对比度不达标）。
- 正文区**没有任何方框**：没有卡片、没有 chip、没有圆角底块；整个面板**唯一有底色的元素是"当前选中的那一样东西"**（底色 + 左侧 accent 条，四处选中统一用这一套）。
- 字号只有几档：条目 16、正文 14/1.8、目录行 13、元信息 11.5。正文行长封顶（阅读态 720、索引态 880）。
- **动效只留一处**：两个态之间的转场。不做满屏 hover 过渡（进度条也不加过渡，它每帧都在变）。
- 键盘焦点必须可见（原来全面板 `outline: none` 且无 `:focus-visible`，等于纯鼠标）。
- **面板里的确认走应用统一的 `ModalDialog`**（`useModal().confirm / choice`），不用 `window.confirm`：
  原生弹窗在 WebView 里是浏览器样式、与主题无关，而且会阻塞渲染进程。删除用 `choice` 之外的三选
  （保存并结束 / 放弃修改 / 继续编辑）——二值化会把「我想接着改」这一档挤掉。
- **上传要有进度**：字节百分比由 XHR 给（fetch 没有上传进度事件），99% 之后改口叫
  「服务端正在处理…」——那段时间是解析落库，不是还在传。

**第三步：发布。** 取件地址（§4.6）经 nginx 暴露 + 只读约束（§4.5）。

**第三步之后**：图片、PDF 的第二刀落地后，`tags` / `links` 那两张死表可以顺势赋予意义（条目之间终于有东西可连）。
