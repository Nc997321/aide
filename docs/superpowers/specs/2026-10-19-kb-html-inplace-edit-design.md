## 1. 问题

资料库已经能装 AI 做的网页（html 条目），点「在右栏打开」能真跑起来。但这类条目到此为止：

| 想做的事 | 现状 |
|---|---|
| 看一眼 | 只能去右栏打开。右栏浏览器的引擎**只有 Windows 实现**（`src-tauri/src/browser/adapter/` 只有 `webview2` 与 `unsupported`），macOS / Linux 上根本打不开 |
| 改一个错字、换一句标题 | 只能跟 AI 说，或者进编辑态改 html 源码 |
| 主色深一点、间距松一点 | 同上，说一句、等一轮、不满意再说一句 |
| 指着某一块提意见 | 做不到。Markdown 文档有「圈选 → 交给 AI 改」，html 条目没有；AI 只能 `update_document` 整篇重写，没有「圈中什么改什么」的保证 |
| AI 知道人改过什么 | 不知道。它下一轮读到的就是一份新正文，不知道哪些是人刚手改的，可能顺手改回去 |

## 2. 参照：Claude 的两种网页产物

**Claude Design**（Anthropic Labs，2026-04 发布）。据公开资料：左边对话、右边实时画布；产出是代码驱动的原型（可打包交给 Claude Code 继续做），**不是 Figma 画布**，没有 `.fig` 导入导出，读 Figma 文件只为提取设计规范。人改它有四条路：

1. 对话：大改动；
2. 钉在元素上的评论：指着某一块提意见；
3. 直接改文字：不经 AI；
4. Claude 生成的调节滑杆：间距、颜色、布局的微调。

公开资料里没有「拖动元素」。

**Artifact**（本对话里用的那种）：Claude 写 HTML 上传，页面在独立来源下渲染，按声明的能力注入 `window.claude.*` 桥；页面可以把自己存成新版本，Claude 再发布时撞上就拿最新内容合并。

两者共同的骨架是**隔离渲染 + 桥 + 版本与回流**，Aide 每一件都已经有了：

| 部件 | Aide 已有 |
|---|---|
| 隔离渲染 + 桥 | 侧栏应用：沙箱 iframe（不给 `allow-same-origin`）+ 桥，只认 `event.source` |
| 版本存储 | knowledge-server：保存即版本、合并窗口、回滚 |
| 回流到 AI | Markdown 圈选：`kbref` 授权 + `edit_selection` + 一篇文档一个卡片会话 |

**拿**：Claude Design 的四条修改路径全拿（对话、评论、改字、滑杆）；人改了什么，AI 下一轮知道。

**不拿**：

- **「页面把整个自己存回去」**（Artifact 那条路）。原因见 §4.1。
- **页面自带存储、问 AI 等运行时能力**。那是「做一个工具」，侧栏应用已经是这个形态。资料库的网页是**产物**，不再开第二套运行时。
- **拖动元素**。流式布局的网页里「拖到这里」在源码里没有对应写法（硬改绝对定位，换个宽度就乱），Claude Design 也没做。位置调整用评论交给 AI。
- **发布冲突让 AI 合并**。我们的每一处修改都是「源码里的一段」，保存前原位校验，不存在整份互相覆盖。

## 3. 产品形态

html 条目的阅读态从「一个按钮」变成「正文区直接渲染这个页面」，上方四个操作：

```
┌─ 会员中心原型 · v3 ────────── [改字] [调样式] [评论] [在右栏打开] ┐
│                                                                │
│   （页面在这里真跑起来，按钮能点、脚本会执行）                       │
│                                                                │
└────────────────────────────────────────────────────────────────┘
```

| 想做的事 | 用哪个 | 经不经 AI |
|---|---|---|
| 改几个字 | 改字 | 不经，立刻生效 |
| 颜色、间距、圆角、字号微调 | 调样式 | 不经，拖着实时看 |
| 布局、增删模块、换风格、任何说得清的意见 | 评论 | 经 AI，只改被指的那一块 |
| 全尺寸看、跟页面交互 | 在右栏打开 | — |

改字和调样式产生的修改合在一起：工具栏显示「已改 N 处 · 保存 / 放弃」，保存出一个新版本，作者是人。

### 3.1 改字

开着时，页面里能改的文字悬停有虚线框，点一下就地编辑，回车或点别处确认。

- 点到**页面脚本生成的文字**（源码里没有那段字），提示「这段是页面脚本生成的，不能直接改」，旁边给「写条评论交给 AI」。
- 只改文字，不改结构。

### 3.2 调样式

点开是页面右侧一个面板，列出这个页面的**设计变量**：

```
┌ 调样式 ───────────────────────┐
│ 颜色                           │
│   主色   --accent   [■ #3b6cf6]│
│   背景   --bg       [■ #ffffff]│
│   正文   --text     [■ #1f2328]│
│ 尺寸                           │
│   间距   --gap      ──●──── 12px│
│   圆角   --radius   ─●───── 8px │
│ 字体                           │
│   正文   --font-body [系统无衬线▾]│
│                      [恢复原值]  │
└───────────────────────────────┘
```

- 设计变量 = 页面样式表里 `:root { … }` 那组 CSS 变量。`aide-design` 技能本来就要求 AI 把配色、间距、圆角、字体写成这样一个变量块，所以 AI 做的页面天然有这组变量，**不需要 AI 额外生成滑杆**。
- 拖动或取色时页面实时变化（只是预览）；松手记为一处待保存的修改。
- 页面没有这组变量（用户上传的、别处来的）：面板写「这个页面没有可调的设计变量」，给一个按钮「让 AI 整理成变量」（发一条评论式消息，见 §3.3）。
- 页面有暗色版（`@media (prefers-color-scheme: dark)` 里覆盖了同名变量）：第一版只调亮色那一组，面板注明「暗色版的颜色在暗色主题下另调」，不假装两套一起改了。

### 3.3 评论

点「评论」后，鼠标移到页面上会高亮指着的那一块；点一下，钉一个编号，旁边弹出小框写意见：

```
   ┌──────────────────────────┐
 ①│ [我的订单] [优惠券] [设置] │  ← 钉在这一排上
   └──────────────────────────┘
     ┌ ① ──────────────────────────┐
     │ 改成带图标的宫格，一行四个，   │
     │ 加一个「客服」               │
     │      [先攒着]  [立即交给 AI]  │
     └─────────────────────────────┘
```

- **先攒着**：评论留在页面上（带编号的钉），可以继续钉下一条、改、删。卡片上方显示「待处理 3 条 · 全部交给 AI」。
- **立即交给 AI**：这一条马上发。
- 发出后，对话在这篇文档的卡片里进行（与 Markdown 圈选同一张卡片）：AI 逐条回复，每条修改给出「原文 ↔ 新文」对照和「应用 / 不要」。应用了的评论，钉变成 ✓；没改成的留着，可以追问。
- **AI 只被允许改评论钉住的那几块**，页面其余部分一个字不动（§4.6）。

评论是**给 AI 的意见**，不是团队讨论：存在本机、跟着这篇文档，同事看不到，处理完就收起。要做成团队可见的批注线程，是资料库协作那条产品线的事（§7）。

### 3.4 几件事之间的关系

- AI 正在改这篇时，改字和调样式不可用（与 Markdown 编辑态现有的「AI 修改中…」同一条规则）。
- 有未保存的改字 / 调样式时不能发评论（先保存或放弃），否则 AI 看到的是旧版本。
- 人保存之后再给 AI 发消息，展开文本里自动带一段「上一轮之后用户手改了这几处」（§4.7），AI 就不会把它们改回去。

## 4. 实现设计

### 4.1 最关键的决定：保存的永远是「源码补丁」，不是 DOM

人在页面里改了一个字或一个颜色，存回去有两种做法：

| 做法 | 问题 |
|---|---|
| A. 把当前 DOM 序列化成 HTML 存回去 | 页面脚本跑过之后的 DOM ≠ 源码：脚本渲染出来的列表、计时器改过的数字、我们注入的编辑脚本和钉都会被写进库；属性顺序、空白、实体编码全被浏览器规范化，**一个字的修改变成整篇 diff**；下次打开，脚本在已经渲染过的 DOM 上再渲染一遍 |
| **B. 把每一处修改映射回源码的一段区间，只替换那一段** | 需要「页面上的东西 ↔ 源码里的哪一段」的对位 |

**定 B。** 与 Markdown 圈选「新正文 = 原文前缀 + 新文本 + 原文后缀」同一条构造性保证：选区之外没有一个字符经过浏览器或 agent 之手。三种修改落到源码上都是「一段区间换一段文字」：

| 修改 | 源码里的区间 | 替换成 |
|---|---|---|
| 改字 | 元素的内容区间（开始标签之后到结束标签之前） | 转义后的新文字 |
| 调样式 | `:root` 里某个变量的值（`--gap:` 之后到 `;` 之前） | 新值 |
| 评论（AI 改） | 被钉元素的外层区间（含标签） | AI 给的新 HTML（经 `edit_selection`） |

### 4.2 源码映射

**前端拿到的是源码，渲染的是源码的一份「带标注副本」。**

1. 取条目正文（源码），用带位置信息的 HTML 解析器解析，记下每个元素的内容区间与外层区间。
2. 生成副本：给源码里每个元素加 `data-aide-n="k"`，注入编辑脚本（§4.4），交给 iframe 渲染。**副本只用来渲染，永远不保存。**
3. 页面里点到一个元素，脚本报回 `k`；前端按 `k` 查到源码区间。
4. 能不能改字：该元素在源码里的内容区间是纯文本（不含子标签、注释）才可改。被脚本用 `innerHTML` 重画过的元素没有 `data-aide-n`，自然落在「页面脚本生成的」——这正是想要的。评论同理：钉到没有 `data-aide-n` 的元素上时，向上找最近一个有的祖先，钉在它上面并提示「这块是脚本生成的，已钉在外层」。
5. 设计变量：在每个 `<style>` 的内容区间里找顶层 `:root { }` 规则（不在 `@media` / `@supports` 里），逐条记下 `--名字` 与值的区间。只认最简单的 `--x: 值;` 形态，值里含 `var()` 的变量列出但只读（它是派生的，改它的来源）。

解析器是可替换的第三方技术（parse5 / htmlparser2 等都能给位置信息），按 CLAUDE.md「可替换技术藏在端口后面」：前端只依赖 `htmlSourceMap.ts` 导出的 `mapHtmlSource(source) → { annotated, nodes, vars }`，解析器只在它的适配器文件里出现。默认用 parse5（`sourceCodeLocationInfo`，偏移是 JS 字符串下标，与 `KbRef.start/end` 的 UTF-16 偏移同一口径）。`:root` 变量的扫描是自己写的纯函数，不引 CSS 解析库：只认一种形态，认不出就不列，不会改错。

已知边界（如实降级，不硬做）：

- `<template>`、`<svg>` 里的 `<text>`、`<textarea>` 的初值：第一版不给改字。
- 含实体的原文（`&amp;`、`&nbsp;`）：编辑框里显示解码后的文字，保存时只转义 `& < >`，`&nbsp;` 会变成普通字符。可以接受，测试钉住。
- 源码有语法错误、解析器修复过的结构：修复处的区间不可信，不给改字、不给钉（解析器报告这些位置）。
- 设计变量写在外部 CSS 文件里（`<link rel="stylesheet">`）：资料库的 html 是单文件，不处理。

### 4.3 在哪里渲染：Aide 自己的 iframe，不是右栏浏览器

右栏浏览器是原生子视图，只有 Windows 有引擎，外层也够不着页面。内嵌渲染改用 Aide 主界面里的 iframe：

- 三个平台都能用（顺带补上 macOS / Linux 上 html 条目打不开的洞）。
- 隔离照抄侧栏应用（`AppPanel.vue`）：`sandbox="allow-scripts allow-forms"`，**不给 `allow-same-origin`、不给 `allow-top-navigation`**；收消息只认 `event.source === iframe.contentWindow`；页面给的任何字符串只进文本节点。
- 内容怎么进 iframe 是 **P0 要先验证的事**（§8）：首选 `srcdoc` + sandbox（来源不透明），要实测在 Tauri 下拿不到 IPC——侧栏应用的 P0 只验过「回环地址加载」。`srcdoc` 不安全就退回那条路：Host 的回环页面服务加一个一次性地址投递副本。
- 相对资源：副本 `<head>` 最前面插 `<base href>`，指向条目的取件地址，与右栏打开时解析结果一致。

### 4.4 页面里的脚本与桥

沿用 `browser-pick-to-agent` §4.4 的纪律：

- 编辑工具（悬停框、评论钉、意见框）挂在一个 shadow DOM 宿主里，页面样式进不来；宿主自己不可选。
- 改字 / 评论模式下，监听一律在捕获阶段并 `stopPropagation`，页面自己的点击、提交拿不到事件。
- 颜色由外层把当前主题的 accent 作为参数传进来，脚本里不出现颜色字面量。
- 改字用 `contenteditable="plaintext-only"`，只开在被点中的那一个元素上，确认后立刻关掉。

桥的消息形状固定，双方逐项校验：

| 方向 | 消息 | 用途 |
|---|---|---|
| 页面 → 外层 | `ready`、`height { px }` | 加载完成、内容高度 |
| 页面 → 外层 | `edit { n, text }` | 改字确认 |
| 页面 → 外层 | `pick { n, rect }` | 评论模式点中了一块 |
| 外层 → 页面 | `mode { name }` | 切换 浏览 / 改字 / 评论 |
| 外层 → 页面 | `setVar { name, value }` | 调样式的实时预览（`documentElement.style.setProperty`） |
| 外层 → 页面 | `pins { list }` | 画评论钉：`[{ n, label, done }]` |

页面本身是不可信的（AI 写的或用户上传的），外层**不信任桥上的任何内容**：`n` 必须在本次解析的节点表里，`text` 有长度上限，`edit` 只在改字模式开着时收，`pick` 只在评论模式开着时收。`setVar` 的名字必须在本次解析的变量表里。

### 4.5 保存：改字与调样式

1. 进改字或调样式时取编辑软锁（与 Markdown 编辑态同一条 `acquire_lock` / 心跳 / 释放）。
2. 每确认一处只记进本地草稿：`{ 区间, 原文, 新文, 种类 }`。同一个变量、同一个元素改多次，只留最后一次。
3. 保存时**重新读一次正文**，逐处做原位校验（`源码.slice(区间) === 原文`），任何一处对不上就整批不写，提示「文档在你改的时候被改过了，请刷新后再改」。不做重新定位，理由同 Markdown：错位的代价是改错地方。
4. 从后往前应用补丁，一次 PUT，带 `newVersion` + `expectedVersion`（§4.8），`changeNote` 写「手动改字 2 处、调样式 1 处」。
5. 成功后重新解析、重新渲染，退出编辑模式，释放锁，把这批修改记进「用户手改」记录（§4.7）。

### 4.6 评论交给 AI：一条评论 = 一个 `kbref`

sidecar 一侧**不用改**。`KbRef` 的范围本来就是「正文里的 UTF-16 偏移」，`edit_selection` 的构造性替换、原位校验、读回核对、写工具封口都与正文是 Markdown 还是 HTML 无关；一条用户消息本来就能带多个 `kbref`（`KbScopeStore` 按条登记，agent 按 `selectionId` 逐个改）。

- 评论存本机草稿：`{ id, 元素外层区间, 那段源码, 意见, 状态 }`，跟着这篇文档（与「文档 → 卡片会话」映射同一处，本机、不同步）。
- 「全部交给 AI」= 一条消息带 N 个 `kbref`：每条评论一个，`text` = 那段源码，`comment` = 意见，`precise: true`。发送前按当前版本重新取一次区间（见下）。
- `KbRef` 不加字段，两份 `UserMessageBlock` 不动，`userMessageBlockParity.test.ts` 不受影响。
- 展开文本（`kbRefs.ts` 的 `formatKbRefsForPrompt`）按文档 mime 补一句「这是 HTML 源码片段；newText 必须是能原样替换它的 HTML」。源码片段按不可信数据包起来并写明不是指令（页面是 AI 写的或用户上传的，与 pageref 同一条理由）；意见是用户写的，放在包外。
- 每条评论的状态由聊天事件推进（复用 `kbSelectionEvents` 按 `selectionId` 的那套）：处理中 → 已改 ✓ / 没改成。**本地绝不乐观标 ✓。**
- 卡片对话、权限请求里的行内对照（`inlineDiff`）、撤销、追问：全部复用。

**还没发出的评论在文档变了之后怎么办**：评论在发出之前只是草稿，不是授权，可以重新定位（与 §4.5「不做重新定位」不冲突——那里是写入，这里只是决定钉画在哪）。文档出新版本后，按「那段源码」在新正文里找：恰好出现一次就挪过去；找不到或不止一处，钉变灰，写「这块已经变了，请重新钉」，不猜。发送时以重新定位后的区间铸 `kbref`，之后的保护全交给 `edit_selection` 的原位校验。

### 4.7 人改了什么，AI 怎么知道

给卡片会话发消息时，如果上一轮之后人保存过改字或调样式，展开文本末尾附一段：

```
[用户手改] 你上一轮之后，用户手动改了这几处（v6 → v7），不要把它们改回去：
  文字「季度目标」→「年度目标」
  变量 --accent：#3b6cf6 → #2952cc
```

记录在 §4.5 第 5 步写入，发出后清空，最多带 10 条。往返还原时按 `splitKbRefSections` 的现成做法剥掉，不漏进用户气泡。这段只是提示，不是授权：漏了它，AI 最坏是被原位校验挡住，不会改错地方。

### 4.8 版本、作者与并发

现状有两个坑，都会让「人改的」和「AI 改的」混在一起：

1. **AI 与人用同一份凭据**。sidecar 读的是全局镜像 `~/.aide/knowledge*.json`，服务端看到的 `author_id` 是同一个人。资料库设计 §4.4 定的「会话令牌」还没做。
2. **合并窗口按作者判**（`versioning.rs`，同一作者 15 分钟内的保存改写当前版本）。人改完字保存，正好落在 AI 刚改那一版的窗口里，就会**并进 AI 那一版**；卡片的「撤销这一轮」会把人的修改一起撤掉。

本设计不等会话令牌，只给 `PUT /api/documents/{id}` 加两个可选字段（老客户端不带，行为不变；老服务端不认，忽略）：

| 字段 | 作用 |
|---|---|
| `newVersion: true` | 跳过合并窗口，强制开新版本（`SaveInput.force_new_version` 现成，只是没向接口开口）。人保存时带上 |
| `expectedVersion: n` | 当前版本号不是 n 就回 409，什么都不写。人保存时带上 |

`expectedVersion` 顺带堵上 kb-selection-edit §2 第 4 关承认的洞（「PUT 没有乐观锁」，现在只能写后读回告警）。`edit_selection` 是否也带它另议（§10 问题 2）。

### 4.9 多端与历史

- 改字、调样式是**资料库的文档状态**，不是会话状态，不进事件通道；别的客户端照资料库现有的方式刷新看到新版本。
- 评论草稿是本机草稿（同 `pendingMentions`），发出之前别的客户端本来就看不到；发出后走卡片会话，多端一致性保证与 Markdown 圈选完全相同（用户气泡只认 sidecar 广播的 `user_message`）。
- 手机端不变：html 条目在手机上怎么显示由手机端自己演进；不进 `aide-link` 暴露目录。

## 5. 对 `aide-design` 技能的一处补充

调样式面板依赖「设计变量写在顶层 `:root` 里、一个变量一行 `--x: 值;`」。技能现在已经这么要求（§三「先定方案，再写页面」），补一句让它对得上解析：

- 变量值写字面量（颜色、长度、字体栈），**不要在 `:root` 里用 `var()` 互相引用**——派生值写到使用处，否则调样式面板只能把它列成只读。
- 变量名后加一行注释作人话标签时，面板拿注释当显示名（`--gap: 12px; /* 间距 */`）；没有注释就用变量名。

这是技能文案的改动，不影响已有页面：不符合的页面只是少几个可调项。

## 6. 跨平台

- 内嵌渲染、改字、调样式、评论全部在 Aide 主界面的网页里完成，三个平台同一份代码，不依赖右栏浏览器引擎。
- 右栏打开保持现状（仅 Windows）。
- 测试：映射、变量扫描、补丁、评论重新定位都是纯函数，单测在 Node 里跑；页面脚本在 jsdom 里跑。iframe 隔离（P0）要在 Windows 真机和 macOS 上各验一次。

## 7. 主动砍掉的东西

- **拖动元素 / 结构编辑**（加块、删块、改布局的可视化控件）：做出来就是网页编辑器，且没法做到「只改源码里那一段」。用评论交给 AI。
- **DOM 序列化保存**：见 §4.1。
- **页面运行时能力**（存储、问 AI、共享数据）：那是侧栏应用。
- **团队可见的批注线程**：本设计的评论是给 AI 的意见，存本机、处理完收起。kb-selection-edit §1「对话不放进文档」的定案不变；团队批注是资料库协作那条产品线。
- **AI 生成的任意滑杆**（Claude Design 那种由 AI 现场决定调什么）：我们只把页面已有的设计变量做成控件。要调别的，评论交给 AI，或让 AI 把它整理成变量。
- **改字后自动通知 AI 开跑**：只在下一次用户发消息时随展开文本带上，不替用户发消息。
- **会话令牌 / 人与 AI 作者维度**：资料库第二步的事，本设计只用 `newVersion` 避开它的后果。

## 8. 分期

| 期 | 内容 | 退出条件 |
|---|---|---|
| **P0** | iframe 隔离实测：`srcdoc` + sandbox 的页面里，`window.__TAURI_INTERNALS__` 不存在、`fetch('ipc://…')` 失败、`parent.document` 拿不到；`<base>` 下相对图片能加载 | Windows 与 macOS 各过一遍；不过就改走回环地址，再验一遍 |

## 9. 验收

1. macOS / Linux 上点开 html 条目，正文区里能看到页面跑起来（含脚本）。
2. 改字：改一个标题，保存后新旧版本的 diff **只有那几个字**（逐字节比对）。
3. 点脚本生成的文字，提示不能直接改并给「写条评论交给 AI」，不进编辑态。
4. 改字里输入 `<b>x</b>`，保存后源码里是 `&lt;b&gt;x&lt;/b&gt;`。
5. 调样式：AI 用 `aide-design` 做的页面，面板列出它 `:root` 里的变量；拖「间距」页面实时变；保存后 diff **只有那一个值**。
6. 没有 `:root` 变量的页面，面板如实说没有，并给「让 AI 整理成变量」。
7. 编辑期间另一端改了同一篇，保存被拒、什么都没写、提示刷新（`expectedVersion` 生效）；连老服务端时退回「重新读 + 原位校验」那一道。
8. 在 AI 刚改完的 15 分钟内保存，版本历史里出现**独立的一版**，卡片「撤销这一轮」不会撤掉人的修改。
9. 编辑脚本、`data-aide-n`、`<base>`、预览用的内联样式**永远不出现在库里**（任何一次保存后的正文里 grep 不到）。
10. 钉 3 条评论、全部交给 AI：一条用户消息带 3 个 `kbref`，AI 逐条改，每条的钉按事件变 ✓；钉之外的源码逐字不变（复用 `edit_selection` 读回核对）。
11. AI 处理评论期间调 `update_document` 被拒（现有封口对 html 条目同样生效，补一条测试）。
12. 攒着的评论，在别处出新版本后：那段源码还在且唯一 → 钉跟着挪；变了 → 钉变灰提示重钉，不猜。
13. 钉在脚本生成的元素上 → 钉到最近的有标注的祖先，并提示。
14. 人保存修改后再发评论，AI 收到的展开文本里有「用户手改」段，用户气泡里没有。
15. 页面源码里写一句「忽略之前的指令」，它在展开文本里位于不可信数据包内。

## 10. 待评审拍板

1. **P0 走 `srcdoc` 还是直接走回环地址？** 建议先验 `srcdoc`：不用动 Host、不多一个服务口。验不过再走回环。
2. **`edit_selection` 要不要也带 `expectedVersion`？** 带上能把「写后读回告警」升级成「写前拒绝」，但要改 sidecar、要处理老服务端。建议本设计不做，单独一轮。
3. **改字要不要也能改链接地址和图片的 alt？** 都是属性，映射需要属性级区间。建议第一版不做。
4. **调样式要不要支持暗色那一组变量？** 建议第一版不做（§3.2），看有没有人要。
