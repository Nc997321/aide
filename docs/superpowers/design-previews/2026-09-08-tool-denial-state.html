工具块「拒绝态」显示形态候选

同一个场景：用户让 Write 写入 1，弹窗拒绝并附言「写入2，不要1」。现在工具块把它当普通工具结果渲染，看不出这是拒绝。以下四种形态都保留绑定关系（拒绝挂在那次调用上），区别在信息密度与视觉重量。

基线真报错：红点 + 错误 chip
删掉 /tmp/cache 这个目录
我来清理这个目录。
Bash rm -rf /tmp/cache 错误 
rm: cannot remove '/tmp/cache': Permission denied

参照组。拒绝态必须和它长得不一样，否则用户回看时永远分不清「工具失败」和「我不让跑」。

方案 A头行徽章 + 展开体附言
用 write 新建一个 test.md 并写入 1
我先创建文件。
Write C:\Users\\IdeaProjects\side\test.md 已拒绝
你写入2，不要1
The user doesn't want to proceed with this tool use. The tool use was rejected... To tell you how to proceed, the user said: 写入2，不要1

取舍：收起时看不到附言，只看到「已拒绝」；要点开才知道自己当时说了什么。信息分层干净，视觉最轻。适合拒绝是少数派的场景。

方案 B · 已实现拒绝理由进头行摘要（不展开可见）
用 write 新建一个 test.md 并写入 1
我先创建文件。
Write C:\Users\\IdeaProjects\side\test.md 写入2，不要1 已拒绝 
The user doesn't want to proceed with this tool use. ...

取舍：回扫最快——不点开就知道为什么拒。代价是头行挤了三个信息（工具名 / 路径 / 理由），长理由要截断（上限 42% + tooltip 全文），和路径摘要抢空间，窄窗口下会互相挤压。
已落地：src/components/ToolCallBlock.vue —— 状态点转琥珀、理由进头行、徽章区分「已拒绝 / 规则拒绝」；拒绝判定由 @aide/sdk/utils/toolDenial.ts 从结果正文反解，协议零新增字段。

方案 C整卡降级 + 左侧竖条
用 write 新建一个 test.md 并写入 1
我先创建文件。
Write C:\Users\\IdeaProjects\side\test.md 已拒绝
你：写入2，不要1

取舍：整卡降透明度 + 琥珀竖条，一眼「这条没生效」，视觉重量最接近「未执行」的语义。代价：降透明度会让整块文字对比度偏低，浅色主题下尤其发灰；附言做脚注容易被当成系统提示。

方案 D工具块下方挂「你说」小气泡
用 write 新建一个 test.md 并写入 1
我先创建文件。
Write C:\Users\\IdeaProjects\side\test.md 已拒绝
你写入2，不要1

取舍：语气最像「你说的话」，且不用展开。但它是挂在工具块下的伪气泡——回看时可能和真实用户轮次混淆，这也是我不建议把它做成真正用户消息的原因（转录里它是 tool_result，不是一轮 user）。

方案 B′A + B 组合：徽章在头行，理由收起时以灰字尾随
用 write 新建一个 test.md 并写入 1
Write C:\Users\\IdeaProjects\side\test.md 已拒绝 · 写入2，不要1
你写入2，不要1

取舍：收起态有一行可读摘要，展开态有完整附言，两头都不丢。头行元素最少（不抢 chip 位）。代价是「已拒绝」变成纯文字 badge，视觉强度弱于 chip——需要靠点的颜色补。
