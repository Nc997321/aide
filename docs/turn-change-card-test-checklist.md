## 0. 前置

**① 起 dev 实例，并确认它跑的是新前端**

```bash
pnpm tauri dev
```

> 本笔只动 `src/`（新组件 + 接线），没有 sidecar / Rust / 协议改动 → **不用** `pnpm build:sidecar`。
> 本机可能同时装着安装版与 dev 版（`tasklist | grep aide.exe` 会看到两个）：安装版**没有**这张卡，
> 一切判据都必须在 **dev 实例**里跑。

**② 判据 0（先跑这条，省得白跑一轮）**：随便发一条会让 Claude 改一个文件的指令（示例："在 `README.md` 末尾加一行 `<!-- 验收探针 -->`"），等它跑完。
- **应该**：消息流最底部出现一张带 accent 描边的卡（卡名 `本轮变更`）。
- **没有出现** → 先查你开对话的实例是不是 dev 实例、以及前端有没有热更新（改 `src/` 后 vite 会热更，未生效就重启 `pnpm tauri dev`）。**别急着当 bug 报**。

**③ 截图通道（agent 自证用）**——本应用的主界面 WebView **不在** `aide-browser` 工具的可达范围内（那是内嵌浏览器面板），所以界面证据靠系统级截图：

```bash
powershell -NoProfile -Command "Add-Type -AssemblyName System.Windows.Forms,System.Drawing; \$b=[System.Windows.Forms.Screen]::PrimaryScreen.Bounds; \$bmp=New-Object System.Drawing.Bitmap \$b.Width,\$b.Height; \$g=[System.Drawing.Graphics]::FromImage(\$bmp); \$g.CopyFromScreen(\$b.Location,[System.Drawing.Point]::Empty,\$b.Size); \$bmp.Save(\"\$env:TEMP\aide-turn-card.png\"); \$g.Dispose(); \$bmp.Dispose()"
```

然后用 Read 工具读那张 PNG（图片会被直接渲染出来）。
截图前把 Aide 窗口放到前台并让对话滚到底；判据里凡写"截图"的都走这条路。

## 1. 判据（机器可判，agent 逐条跑）

> 每条写清：**操作 → 判据 → 判分**。判分只有 PASS / FAIL 两档；FAIL 必须附截图与一句现象。

### 判据 1：不打开侧栏就能说出规模
- **操作**：完成判据 0 那条指令后，**不要**打开任何侧栏；截图。
- **判据**：卡片行 2 以 `<N> 个文件` 开头，其后是 `+a`（与）`−b`；数字与改动量一致（`+a −b` = 本轮各文件增删之和）。
- **判分**：能读到文件数与行数 = PASS。数字与文件实际改动不符 = FAIL（把数字与 `git diff --stat` 一起写进记录）。

### 判据 2：从卡到 diff ≤ 2 击
- **操作**：点卡片非按钮区（第 1 击，展开清单）→ 点其中一行文件（第 2 击）。
- **判据**：出现该文件的 diff 窗口（标题是文件路径）。
- **判分**：≤2 击出窗口 = PASS；需要第 3 击或没弹 = FAIL。

### 判据 3：`变更面板 ↗` 是「确保显示」，不是 toggle（**本笔最容易错的一条**）
- **操作**：先按 `Ctrl+2` 打开右栏变更面板（确认它已展开且停在「变更」tab）→ 再点卡上的 `变更面板 ↗`。
- **判据**：面板**仍然展开**且仍在「变更」tab（不得被收起来）。
- **判分**：面板没被收起 = PASS；点一下面板收了 = FAIL（这正是 spec §2.3.1 写死的那条判据）。
- **补充**：面板收起时点它 → 应展开并切到变更 tab（同一动作的另一种起始态）。

### 判据 4：进行中 = `正在改`，且没有出口
- **操作**：发一条会让 Claude 改**多个**文件的指令（示例："把 `README.md` 和 `CLAUDE.md` 各改一处措辞"），**在它跑的过程中**截图（多截两张，看数字会不会长）。
- **判据**：卡名 `正在改` + 左侧呼吸点；行 1 右端是 `N 个文件`；**没有** `变更面板 ↗`、**没有** `展开`；数字随编辑增长（后一张截图的数字 ≥ 前一张）。
- **判分**：形态全对且数字会动 = PASS。

### 判据 5：零变更的轮不出现（连"0 个文件"也不出现）
- **操作**：发一条纯问答（示例："这个项目用什么包管理器？"）→ 等它跑完 → 截图。
- **判据**：流尾**没有**卡片；也不出现 `正在改 · 0 个文件` 之类。
- **判分**：无卡 = PASS。（注意：上一轮的账单也跟着退场，这是设计如此——见第 3 节）

### 判据 6：长会话不堆积
- **操作**：连续发 3–5 条会改文件的指令，每轮跑完截一张图。
- **判据**：流尾**始终只有一张卡**（没有每轮叠一张）；卡上的数字是**当前轮**的，不是历史累计。
- **判分**：始终一张 = PASS；出现两张以上 = FAIL。

### 判据 7：重载后一致
- **操作**：记下卡上的三个数字 → 重载前端（`Ctrl+R`；不行就重开该 tab）→ 截图。
- **判据**：卡片仍在**流尾**，三个数字与重载前一致。
- **判分**：一致 = PASS（轮次从磁盘 `<sid>-changes.json` 加载，不依赖内存态）。

### 判据 8：卡片增高时的滚动锚定（spec §6.4 特意留的实测项）
- **操作**：停在流底 → 点卡片展开（清单变高）→ 再收起；然后上翻几屏看历史，观察右下角「回到底部」浮标。
- **判据**：展开/收起时视口不乱跳（不该被甩到别处）；上翻后浮标正常出现，点击能回到流底。
- **判分**：都正常 = PASS。**打架了也要如实记下来**——那是 spec §6.4 预告过的"另一笔改动"，不是本笔的失败，但必须留证据（哪一步、跳成什么样、截图）。

## 2. 反向自检（判据 0 之外的"别验错东西"）

| 探什么 | 期望 |
|---|---|
| 卡面描边颜色 | accent 蓝紫，不是灰（灰调说明渲染成了"进行中"形态） |
| `变更面板 ↗` 的字形 | `↗` 是 U+2197（不是 `>` 或 `→`） |
| 删除号字形 | `−` 是 U+2212（比 ASCII 连字符长、居中），卡上绝不出现 `-2` 这种 |
| 无变更的轮 | 流尾干净（判据 5） |

## 3. 只有人能判的两件事 + 三件"别当 bug"的设计

**人判**：
1. 宽窗形态（spec §11 待定项 1）：把窗口拉到很宽，统计行右侧的留白是否可接受？（统计行封顶 480px，余量甩右侧——原型值，宽窗最终形态当时未定。）
2. 观感：卡名 10.5px 拉字距、19px 大数字、比例条贴右端——与原型页 `docs/prototypes/2026-09-24-turn-change-footer.html` 的 §01/§03 对照着看，是否同一张脸。

**别当 bug**（本笔明确不做，见 spec §5.4/§6.3/§8）：
1. **往回翻看不到历史轮的卡**——历史账单由右栏变更面板承担，卡上的 `变更面板 ↗` 就是通往它的门。
2. **卡上没有「撤回整轮」**——我们的 revert = 杀进程 + 截断 jsonl + 逐文件还原，不可逆；它留在有确认弹窗的面板。展开后的**单文件**撤回是有的（与面板一致）。
3. **没有淡入动效**——spec §6.3 拍板砍掉（YAGNI）。
4. 另：**分屏里非聚焦的那一组看不到卡**（那份数据绑的是聚焦组会话，避免把 A 组的数字显示到 B 组）。
