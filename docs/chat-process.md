# 桌面聊天的过程折叠

正文保留原位。连续的工具调用、子代理和思考共用一个过程入口，入口显示最后一条指令，而不是另占一行显示历史摘要。正文、图片、引用或系统卡片切开过程组，不调整消息顺序。

- 点击当前指令，同步打开该指令的详情和历史过程。历史项可继续点开查看原始输出、diff 或子代理时间线。
- 普通读取、搜索、命令默认只显示头行，不在头行下面自动展示输出。
- Edit / MultiEdit / Write / NotebookEdit 沿用原有的当前 diff 片段预览。执行完成、追加正文或思考时不提前收回；下一条指令出现后，旧修改收进历史。
- 新指令到达或回答结束时，过程组默认收起；之后仍可手动展开。打开历史消息时不自动展开修改预览。
- 收起时仍提示历史失败数量；当前指令的权限拒绝、后台运行、文件定位等入口沿用现有组件。
- 「显示思考过程」关闭时不展示思考正文，纯思考阶段只留“正在思考…”提示。
- 用户消息中的文件附件、知识库/网页选区、图片和系统回报不作为执行过程折叠。

## 实现边界

`src/utils/blockSegments.ts` 生成桌面渲染分段，并确定“当前”指令。当前身份不以工具是否仍在运行判断，普通正文和思考不抢占最后一条指令。

`src/components/ProcessGroup.vue` 独占组展开状态；当前指令切换与回答结束分别触发收起，后者同样作用于较早被手动展开的组。当前步骤按指令 ID 重建，避免不同文件的 diff 复用行号缓存。下层 `ProcessGroup/ProcessStep.vue` 适配现有 ToolCallBlock、SubagentCallBlock、ThinkingBlock，通过受控展开和插槽组合历史。工具详情、diff 和权限提示没有平行实现。

这是桌面展示行为，未修改共享事件协议或手机端渲染。
