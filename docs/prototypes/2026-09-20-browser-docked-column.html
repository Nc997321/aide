这条方案拿到什么

  • 边聊边看：聊天与页面同屏，会话切换不再把浏览器踢掉（现状 App.vue:401 选会话就关面板）。
  • agent 工具回到主路径：视图可见 ⇒ 有合成帧 ⇒ browser_screenshot / 过渡类断言可用；不用再要求用户"切到前台"。
  • 改动面小：PaneLayout、聊天渲染、tab 联合类型一行不动；rectOf() / viewAllowed / 注册表保活全部复用。

机制不变的那部分（别被原型骗了）

  • 原型里的页面是 <div>，真机上是原生 WebView2 子视图，按那个 rect 浮在窗口上。
  • 所以：任何浮层压上来都必须让位（点上面的按钮看效果），洞那一列不能有 HTML 覆盖物，工具栏要排在洞外。
  • 窗口最小化 / 被完全遮挡时，Chromium 照样判后台 —— 这一条谁也躲不掉。

待你拍板的（原型里都做成了开关）

  • 默认落哪边：主区右侧（聊天左、页面右，本原型）还是左侧？
  • 要不要保留最大化形态（点按钮看）——读长文档/调试时铺满更舒服，代价是多一个状态。
  • 默认列宽与是否记忆（本原型拖到 440px 起步，右栏 180px 保持不动）。
  • 与「插件 / 知识库 / 自动化」的关系：它们开时本列是收起（保持现状互斥）还是继续停靠、只让出主区？
