输入框 @ 补全 · 交互与外观

确认对象：输入 @ 弹出候选（像 / 菜单），路径每敲一个分隔符就换到该目录下——@src/ → @src/components/ 逐级跟随； 并能 @ 到其它项目（= 其它已注册工作区），选中即走既有的「@目录即授权」链。

  • → 或行尾「进入」＝下钻一层（文本变 @src/components/，不带尾空格）；对项目行同样是「进这个项目」
  • 回车 / Tab / 点行＝引用该项：文件=芯片，文件夹/项目=芯片（发送时即 @目录 授权，Rust 侧判「已注册工作区」才过闸）
  • @foo 先列本层前缀命中，再补全仓模糊命中（gitignore 感知，只回文件）；同层打字零 IPC
  • 弹层沿用 / 菜单的位置（输入盒上方、贴左右边距），锚在输入盒而非光标

本轮新增：「项目」这一层候选（第 1 节可直接打 @ 看；第 3 节看它怎么被过滤）。 仍然只有两件事要你点头：项目行放最前、右侧显示父目录，以及模糊兜底行的区分方式（已定变体 B，这里保留 A 版供对照）。

2 · 四种形态对照 同上弹层，固定状态渲染，便于横向比较密度
① 裸 @：项目在最前 本轮新增
项目 → 本层目录 → 本层文件
@
项目行：项目名 + 「项目」弱标签 + 右侧父目录（同名项目靠它区分，RTL 省略保尾部）+ 「→ 进入」。回车＝引用（授权）该项目，→＝进去逐级挑它的文件。
② 本层下钻：@src/ 已敲分隔符
列出该目录的子项
@src/
一旦敲了分隔符就不再列项目——你已经在某个目录里了。
③ 项目按名匹配：@back 本轮新增
有叶子时项目同样参与匹配
@back
本层没有「back」开头的条目，兜底模糊也回空 ⇒ 只剩项目这一行。项目名匹配用的是包含（不是前缀），@api 也能命中 backend-api。
④ 三类混排 · 变体 B
@s：项目 + 本层目录 + 全仓兜底
@s
项目用 accent 色「项目」标签、兜底用灰「全仓」标签——两种来源不能长一样；本层命中行尾留空，一眼可辨。
3 · 进项目之后 本轮新增 项目行按 → 或点「进入」
⑤ @C:\work\backend-api/
列的是那个项目的子项
@C:\work\backend-api/
于是「@ 到别的项目里的具体文件」就是顺路的：进项目 → 逐级 → 回车拿文件芯片。绝对路径 token 的列目录能力已有单测覆盖（工作区外照列）。
被挡掉的项目（不进候选）
C:\work当前会话工作区的祖先——「其它项目」是"不是我所在的地方"
C:\work\frontend当前会话工作区自己——引用自己的 cwd 没有意义（本层条目已在候选里）
C:\work\gatewaymissing：登记的路径已经不在了，列出来只会让人选了才发现
三条都是纯前端过滤（`useWorkspaces().workspaces` 里就带 `missing`；自身/祖先用 SDK 现成的 isSameOrInside——发送侧剔主根子树用的同一个判据）。
4 · 边界态 两种"菜单不该出现"的情况
⑥ 空态：@zzz 无任何命中
@zzz
不弹空菜单（弹一个「无匹配」比不弹更吵），保留文本、照常输入。
⑦ 光标离开 token：文本里的 @src/ 仍在，但光标已跳到句尾
@src/ 看下这个目录里有什么▏
判定是「光标锚定」的：光标不在 token 末端就关菜单（否则编辑器里改上文会莫名弹层）。
⑧ 项目很多：8 行上限共用
项目挤掉本层条目
@
已知取舍：项目超过 8 个时本层条目会看不见（往上一级/往下敲一个字母即缓解）。真成问题再改分组折叠。
